Building a Tiny‑On‑Board Anomaly Detector for ESA Satellites

TL;DR — We’re training a lightweight anomaly detector that can run on edge neuromorphic hardware (Akida). It learns what “normal” looks like from satellite telemetry and flags surprises via forecasting errors—great when labels are scarce and compute is tight. We pair self‑supervised learning (contrastive + masked denoising) with an Akida‑friendly CNN/SNN so it’s both accurate and deployable.

Why we did this

Satellite ops live and die by fast anomaly response, but ships and ground stations aren’t always available. The goal: catch anomalies quickly with minimal memory/compute and make it work on Akida for true edge inference.

The data

We’re using the **ESA Anomaly Detection Benchmark (ESA‑ADB)**—multivariate telemetry from real missions meant to raise the baseline for anomaly detection. Events are categorized as anomalies, nominal rare events, and communication gaps; the test split excludes comm gaps so the task is to find anomalies + rare nominal events.

Two handy, practical bits as you get started:

  • It’s multivariate time series (many sensors over time), so representation learning matters.
  • A 6‑channel subset (41–46) is a great sandbox before you scale to the full set.

There’s also a helpful taxonomy: coarse Class labels (e.g., class_4, class_7, class_11) and finer Subclass. Even if you’re doing binary detection, this structure is gold for diagnostics and a future multi‑class head.

How the model learns (without babysitting it)

Self‑supervised pretraining is the backbone. We explore:

  • Contrastive ideas (Siamese encoders; positives close, negatives far).
  • CPC (Contrastive Predictive Coding) to use context to predict the future in latent space (think: “understand the pattern, not the noise”).
  • Non‑contrastive tricks (BYOL/SimSiam) with predictors + stop‑gradient to avoid collapse when negatives are scarce.

Our working recipe is hybrid SSL: a contrastive loss + masked denoising reconstruction in one training step (ssl_train_step). We like Huber for the reconstruction part—it’s robust to outliers you’ll inevitably see in telemetry.

At inference time, we forecast a short horizon and treat |prediction − observation| as the anomaly score—no labels needed if you’ve learned “normal” well.

Architecture—tuned for Akida (gotchas included)

Design for the hardware first. A few rules we ran into:

  • Asymmetric conv kernels (e.g., 7×1) are not allowed. Use symmetric alternatives (e.g., 7×7). This one bit us until we re‑fit the backbone.
  • Stick to Akida‑friendly ops: ReLU6, MaxPooling, GlobalAveragePooling; keep it simple and conversion‑safe.
  • The head is a small forecasting MLP that reshapes to [horizon, channels]; residuals become the anomaly score.

Pro tip: Minimize early channel mixing, focus first on temporal features, then add a light 1×1 conv for channel fusion if needed.

Training workflow & small fixes that saved us hours

  • Train mostly on normal segments (y=0) so the model internalizes “healthy” behavior; it becomes sensitive to deviations at test time.
  • Windowing matters. A setup that worked well for us: 1‑hour input → 30‑minute forecast.
  • Metrics/Callbacks: If you’re doing binary detection, compile with AUC and monitor val_auc; don’t monitor val_auroc unless you actually added it—otherwise your best model never saves. For SSL/regression phases, monitor val_loss and drop “accuracy” (it’s meaningless there).
  • Normalization buglet: In estimate_norm_stats_ssl, using x.shape[0] can be None with dynamic batches—switch to tf.shape when tallying.
  • Reproducibility: Keep it containerized (docker build …, docker run …) and use a couple of SLURM one‑liners for queueing and cleanup while iterating.

How we’ll judge success

  • Primary: ROC‑AUC & PR‑AUC if labels are available (Anomaly vs Rare Event).
  • Unsupervised: Percentile‑based thresholds over forecasting residuals for early flags.
  • By taxonomy: Report by Class/Subclass to spot blind spots (e.g., strong on class_7, weak on class_9).

What surprised us

  1. SNN/Akida constraints are real—design with the allowed ops/kernels from day one.
  2. Data understanding first: relationships among channels and the time range you choose can make or break you.
  3. Right tool, right layers: time‑series structure should drive kernel sizes and mixing strategy.
  4. Own every line: black‑box DL is a trap; most issues were fixed in training loops/callbacks, not just models.

What’s next

  • Lock in the Akida‑compliant backbone (sym kernels, GAP, ReLU6) and validate on the 6‑channel subset before scaling up.
  • Keep iterating on the hybrid SSL (contrastive + denoising) and time‑series augmentations (masking, noise, time shuffle) to harden robustness.
  • Clean up metrics/checkpoints across phases and start publishing results per Class/Subclass; that’s your roadmap to a multi‑class head later.
